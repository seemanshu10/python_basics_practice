## 🎯 AP. Basic GIT Branching Workflow

### Task Objectives
* Work inside the existing repository: git-basics-practice.
* Create and switch to a new branch using Visual Studio Code.
* Modify an existing file or create a new one.
* Stage, commit, and publish the new branch to GitHub.
* View the new branch on GitHub and compare it with the main branch.
* Submit the direct link to the new branch for instructor review.

### Instructions
* Use Existing Repository:
  * Open the previously used repository: git-basics-practice.
* Create and Switch to a New Branch:
  * Create a new branch named exactly: feature/branch-practice.
  * Use VS Code’s Source Control panel or terminal to create and switch branches.
* Make File Changes:
  * Modify the hello_git.py file by adding a second print statement.
  * Alternatively, create a new file if preferred.
* Stage and Commit the Changes:
  * Stage the changes using Source Control
  * Commit with a message like: Update hello_git.py on feature branch.
* Push the Branch to GitHub:
  * Publish the new branch to the remote repository.
* View and Compare on GitHub:
  * Go to the repository on GitHub.
  * Confirm the branch feature/branch-practice exists.
  * Use GitHub’s UI to compare it with the main branch.
* Submit Your Branch Link:
  * Copy the URL to your branch (e.g., [https://github.com/your-username/git-basics-practice/tree/feature/branch-practice](https://github.com/your-username/git-basics-practice/tree/feature/branch-practice)) and submit it for review.

### Sample Output
**hello_git.py (after change):**
```
print("Hello from Git!")
print("This change is on the feature/branch-practice branch.")
```
**GitHub View:**
* Branch: feature/branch-practice
* Commit message is visible
* Differences with main are shown in the compare view
